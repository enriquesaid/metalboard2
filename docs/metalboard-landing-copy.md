### Bloco de contraste

**Título**

Menos contexto espalhado. Mais continuidade.

**Texto**

Uma ideia começa numa nota, vira um teste no terminal, consulta uma API e termina em um componente. No Metalboard, cada etapa pode ficar no canvas — relacionada à anterior e pronta para alimentar a próxima.

**Antes**

Abas, notas e outputs separados.

**Depois**

Um fluxo visual onde contexto e resultado permanecem juntos.

### Bloco de inputs e outputs

**Título**

Faça uma ideia responder.

**Texto**

Elementos não precisam ser apenas caixas paradas. Um output pode alimentar outro elemento com uma referência simples, ser transformado e reaparecer no ponto certo do fluxo.

**Exemplo visual**

`Fetch → %request.data.users[0].name% → componente`

## Princípios psicológicos usados

- **JTBD:** a copy começa pelo trabalho de manter exploração e execução conectadas.
- **Contraste:** “antes/depois” torna o custo da fragmentação visível sem alegar uma métrica.
- **Redução de ativação:** um CTA único e concreto (“Começar um board”) pede uma primeira ação pequena.
- **Lei de Hick:** os recursos aparecem agrupados por fluxo, não como uma lista extensa de funcionalidades no hero.
- **Efeito IKEA:** “coloque a primeira peça” convida o usuário a criar algo próprio desde o primeiro contato.
- **Aversão à perda, com cuidado:** “sem perder o fio” nomeia a perda de contexto, sem usar medo ou urgência artificial.
- **Transparência:** não usa depoimentos, números, logos ou promessas que ainda não foram comprovados.
